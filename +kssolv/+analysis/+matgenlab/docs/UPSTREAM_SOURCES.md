# matgenlab upstream sources

## Frozen compatibility baseline

matgenlab targets two official Materials Project repositories at exact commits:

| Source | Tag | Frozen commit | Commit date | License |
|---|---|---|---|---|
| `materialsproject/pymatgen` | `v2026.5.4` | `8495e941504cd5123701635b6572942c78d9589c` | 2026-05-05 | MIT |
| `materialsproject/pymatgen-core` | `v2026.7.24` | `c71faa7a95df9bbcd20cb3d14ff112d0f72d8e39` | 2026-07-24 | MIT |

The authoritative machine-readable declaration is
`dev/matgenlab/upstream_baseline.json`. The tags are human-friendly labels; the
full commit hashes are the compatibility identity.

## Traceability rule

Every matgenlab implementation item must link to one or more rows from
`dev/matgenlab/inventory/api.csv`, tests from `tests.csv`, and fixtures from
`fixtures.csv`. A ported algorithm must additionally record its upstream source
ID, module path, frozen commit, and material local deviations in its MATLAB
documentation or the implementation ledger.

The inventory is generated by
`dev/matgenlab/generate_upstream_inventory.py`. It validates `git rev-parse
HEAD`, parses public Python declarations with the standard-library AST, and
hashes source/test/fixture files. Regeneration must be byte-for-byte clean before
the baseline or implementation ledger is accepted.

## Licensing and redistribution

Both upstream projects are MIT licensed. Direct translations and derived data
must retain the relevant Materials Project copyright and MIT notice. The
repository-level third-party notices must be updated before distributing
translated upstream code or upstream data.

External executables, databases, pseudopotentials, and reference files used by
pymatgen may have different terms. Their presence in an upstream test or API
inventory does not grant redistribution rights. In particular, restricted
POTCAR data must never be committed or bundled; matgenlab may only expose a
user-configured data location and compatible metadata/parsing behavior.

## Updating the baseline

Changing either frozen commit is a deliberate compatibility release:

1. update `upstream_baseline.json` with official repository, tag, full commit,
   commit date, roots, and license;
2. regenerate all JSON/CSV inventory files;
3. review the API/test/fixture diff and create implementation-ledger items;
4. regenerate differential-test oracles;
5. update compatibility documentation and release notes.

Silent movement of a tag or testing against an unrecorded checkout is not an
accepted baseline update.
